Module · module nostr · layer discovery · v0.0.1 · IRI https://torrent-schema.github.io/nostr

Finding a torrent in the first place. Everything below this layer starts from an infohash already in hand; this module is where it comes from. NIP-35 publishes a torrent as a signed Nostr event of kind 2003: enough to search for it and to build its magnet link, and no more — no .torrent file travels, the info dictionary is fetched from the swarm (BEP 9) and verified against the hash. It is the one decentralised index BitTorrent has: a tracker knows hashes, not names; the DHT knows hashes, not names; a kind 2003 event is a name, a hash, and a signature saying who said so. This module writes the event down as data: its tags as fields, the magnet it yields, the projection from a MetaInfo onto it and exactly what that projection drops. Written from a real event, the one that announces the txbt4 UTXO snapshot, checked against the .torrent it was made from.

See also: https://github.com/nostr-protocol/nips/blob/master/35.md
