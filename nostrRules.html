RuleSet · module nostr · IRI https://torrent-schema.github.io/nostrRules

What a kind 2003 event must satisfy to be a listing at all, and — when the .torrent is also at hand — to be a listing of that torrent. Each rule's error code is what the codec reports.

9 rules · scope nostr

#ruleerror codecheck
1the kind is 2003nostr-bad-kindkind == 2003
2exactly one 'x' tag, 40 lowercase hexnostr-bad-xcount(tags named 'x') == 1 and matches /^[0-9a-f]{40}$/ — uppercase is a different string to a relay search even if the same hash
3a 'title' tag with a non-empty valuenostr-no-titletitle present and not blank
4every 'file' tag has a name, and its size if given is a decimal integernostr-bad-filetag.length >= 2 and (tag[2] absent or matches /^[0-9]+$/)
5every 'tracker' tag is an announce URLnostr-bad-trackerparses as a URL with scheme udp, http, https, ws or wss. A web seed in a 'tracker' tag passes this rule: the schema cannot tell them apart, which is the NIP's gap, not the event's
6every 'i' tag is 'prefix:id'nostr-bad-referencecontains ':' with a non-empty prefix; a prefix outside ReferencePrefix is reported as 'unknown', not an error
7the id is the hash of the eventnostr-bad-idid == hex(sha256(serialisation)) — NIP-01; an event failing this was altered after signing or never signed at all
8the signature verifiesnostr-bad-sigBIP-340 verify(sig, id, pubkey). Not computed by the reference codec, which carries no secp256k1; a client must
9with the .torrent at hand: the hash and the files are itsnostr-torrent-mismatchx == infohash(meta) and every file tag names a file of the torrent with its length (a '.' name matches the whole torrent's totalLength)
